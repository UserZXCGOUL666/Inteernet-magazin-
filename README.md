# Минималистичный интернет-магазин

Готовый исходный проект на Next.js, React и TypeScript для размещения на Vercel. Тёмный графитовый интерфейс, светлый лаймовый акцент, адаптация под телефон. Название «магазин» — нейтральная подпись, без придуманного бренда.

## Что работает

- Каталог одежды и аксессуаров; поиск, разделы, категории, размеры, диапазон цен, сортировка.
- Карточка товара с несколькими фотографиями, выбором размера и цвета.
- Избранное и корзина с сохранением в браузере.
- Оформление заявки с именем, телефоном, способом получения и комментарием.
- Панель владельца прямо на сайте: вход с логином `admin` и паролем, добавление и редактирование товаров, загрузка до четырёх фотографий, цены, скидки, размеры, цвета, общий остаток, скрытие и публикация.
- Просмотр последних 200 заявок, изменение статуса, отмена с возвратом остатка.
- Общая база и фотографии в Supabase, права владельца на уровне базы (RLS).

**Онлайн-оплата не подключена.** Заказ оформляется заявкой; оплату, срок и стоимость доставки продавец согласует с покупателем. Уведомления в Telegram/email, интеграция с перевозчиками и отдельные остатки по каждому размеру в текущую версию не входят.

## Быстро посмотреть

Требуется Node.js 22 или новее.

```bash
npm ci
npm run dev
```

Откройте `http://localhost:3000`. Без Supabase сайт автоматически работает в явно обозначенном деморежиме. Демо-товары, фотографии, изменения и заявки сохраняются только в этом браузере. Панель открывается кнопкой «Вход для владельца». Логин — `admin`, случайный пароль из 12 символов выдан отдельно в сообщении вместе с архивом. В исходниках есть только серверный scrypt-хеш демонстрационного пароля, открытый пароль в проект не записан. Демо-вход не создаёт учётную запись в Supabase и не предоставляет доступ к боевым данным.

Это режим знакомства с интерфейсом, а не общая база магазина. Если блок «Демонстрационный магазин» виден после публикации, реальная база ещё не подключена.

## Подключить реальный магазин

### 1. Supabase: база и фотографии

1. Создайте новый проект в [Supabase](https://supabase.com).
2. В **SQL Editor** вставьте весь файл `supabase/schema.sql` и выполните. Скрипт рассчитан на однократный запуск в новом проекте: он создаёт таблицы, защищённые функции оформления заявок, правила доступа и публичный бакет `product-images`.
3. В **Authentication → Users → Add user** создайте пользователя владельца с вашей почтой и выданным паролем из 12 символов (или задайте новый). На сайте вы будете вводить логин `admin`; почта нужна для связи этого логина с учётной записью. Для входа почта должна быть подтверждена (при ручном создании отметьте **Auto Confirm User**).
4. Скопируйте UUID созданного пользователя и выполните в SQL Editor:

```sql
insert into public.store_admins(user_id)
values ('UUID-ПОЛЬЗОВАТЕЛЯ-ИЗ-AUTHENTICATION');
```

5. Скопируйте **Project URL** и **Publishable key** из настроек проекта/API Keys. Также поддерживается старый **anon key**. Не используйте `service_role` или secret key: у них расширенные права, их нельзя передавать в браузер.
6. Отключите ненужную публичную регистрацию пользователей в настройках Supabase Auth. Регистрации покупателей на сайте нет; запись в `store_admins` может добавлять только владелец базы.

Для локального подключения скопируйте `.env.example` в `.env.local` и заполните:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=YOUR-PUBLISHABLE-KEY
NEXT_PUBLIC_DEMO_MODE=false
ADMIN_EMAIL=YOUR-OWNER-EMAIL
```

**`ADMIN_EMAIL` — серверная переменная, без префикса `NEXT_PUBLIC_`.** Она должна совпадать с почтой пользователя владельца в Supabase Auth. Боевой пароль проверяет Supabase; демонстрационный хеш никогда не заменяет эту проверку. При смене пароля реальной учётной записи используйте управление пользователями Supabase.

Перезапустите приложение после изменения переменных. Настоящий каталог изначально пустой; тестовые товары в базу не копируются. Добавьте собственные товары через панель владельца.

### 2. Vercel

1. Распакуйте проект и загрузите его в свой GitHub-репозиторий. `package.json` должен находиться в корне репозитория; если загрузили родительскую папку, задайте **Root Directory** на папку проекта.
2. В [Vercel](https://vercel.com/new) выберите **Add New → Project** и импортируйте репозиторий.
3. Framework Preset: **Next.js**. Install Command: `npm ci`. Build Command: `npm run build`. Output Directory оставьте стандартным, без ручного значения.
4. В **Environment Variables** добавьте `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` `NEXT_PUBLIC_DEMO_MODE=false` и серверную переменную `ADMIN_EMAIL` с почтой владельца для нужных окружений. Переменные с префиксом `NEXT_PUBLIC_` встраиваются при сборке; пароль в переменные фронтенда не добавляйте.
5. Нажмите **Deploy**. При последующем изменении переменных выполните **Redeploy**.
6. Откройте сайт → «Вход для владельца» → введите логин `admin` и пароль созданной учётной записи владельца. Прямая ссылка для открытия панели: `https://ВАШ-САЙТ.vercel.app/?admin=1`.

Не коммитьте `.env.local`. Из исходников и публичного ключа нельзя получить права владельца: запись товаров, доступ к заявкам и загрузка фото дополнительно проверяются базой.

## Что ещё нужно для запуска

**Необходимо:** подключить Supabase и учётную запись владельца; выставить переменные Vercel; загрузить реальные фотографии, описания, цены и остатки; указать реальные контакты и условия получения; проверить заказ и работу панели с телефона и компьютера. Документы по оплате, возвратам и обработке контактов покупателей нужно подготовить под вашу страну и способ работы.

**Следующие улучшения:** уведомления о заявках в Telegram/email, остатки отдельно по размеру и цвету, защита форм от спама, резервные копии, отдельные ссылки на товары и SEO. Онлайн-оплату и автоматическую доставку подключайте, если они нужны вашему процессу. Для оплаты потребуется серверная проверка уведомлений платёжного провайдера и отдельное состояние оплаты, а не только кнопка на странице.

## Перед открытием для покупателей

Замените демонстрационную главную фотографию и заполните каталог своими товарами. В `components/Storefront.tsx` находятся тексты главного экрана и раздела «Доставка и оплата». Сейчас получение и оплата согласуются по телефону. При необходимости добавьте ваши реальные контакты, условия и реквизиты. Состав и материалы демонстрационных товаров не являются описаниями реального ассортимента.

В текущей модели остаток один на товар, общий для всех размеров и цветов. При отправке заявки база резервирует этот остаток. При отмене заявки владельцем остаток восстанавливается один раз. Отменённую заявку нельзя открыть повторно. Удаления товара нет: ненужные товары можно скрыть, история заявок сохраняется.

Заявки доступны в панели, автоматически отправлять их в мессенджер сайт не будет. Таблица отображает последние 200 заявок; полная история остаётся в базе.

## Проверки

```bash
npm test
npm run typecheck
npm run build
```

Тесты проверяют серверный вход, запрет входа с неправильным паролем, отсутствие обхода боевой авторизации через деморежим, ограничение запросов по размеру, фильтры, расчёт суммы, варианты и общий остаток. SQL-схема дополнительно выполняется в локальном PostgreSQL-совместимом PGlite: проверяются анонимный доступ, запрет повышения прав, защищённое оформление, серверный расчёт цены, повторная отправка без дубликатов, отмена и возврат остатков.

Проверены production-сборка, TypeScript и автоматические тесты. Полная визуальная проверка в браузере и интеграция с вашим живым Supabase/Vercel не выполнялись: в среде подготовки не было работающего браузерного предпросмотра и ключей вашего проекта.

## Структура

| Файл / папка                   | Назначение                                                    |
| ------------------------------ | ------------------------------------------------------------- |
| `components/Storefront.tsx`    | Каталог, избранное, карточка, корзина и оформление            |
| `components/Admin.tsx`         | Вход, товары, фотографии и заявки                             |
| `components/Modal.tsx`         | Диалоги, клавиатурная навигация и удержание фокуса            |
| `app/globals.css`              | Тёмный интерфейс и адаптивные стили                           |
| `lib/data.ts`                  | Только демонстрационные товары                                |
| `lib/catalog.ts`               | Фильтрация, валидация корзины и расчёт                        |
| `lib/supabase.ts`              | Подключение Supabase и выбор деморежима                       |
| `app/api/admin/login/route.ts` | Серверный вход с логином `admin`                              |
| `lib/server`                   | Серверная проверка демонстрационного пароля и обработка входа |
| `supabase/schema.sql`          | База, RLS, хранилище, оформление и статусы                    |
| `.env.example`                 | Шаблон переменных Vercel / локального запуска                 |
| `public/images`                | Локальные демонстрационные фотографии                         |

Доступ к покупке не требует регистрации. Панель входит через серверный маршрут `/api/admin/login`: логин `admin` сопоставляется с серверной переменной `ADMIN_EMAIL`, Supabase проверяет пароль, а сервер проверяет запись в `store_admins`. Только после этого браузер получает сессию Supabase Auth. Без настроенного `ADMIN_EMAIL` боевой вход закрыт. В демонстрационном режиме проверяется только scrypt-хеш демонстрационного пароля; данные этого режима остаются локальными и не подходят для работы с настоящими покупателями. Публичные фотографии доступны по URL, персональные данные заявок защищены RLS. Функция оформления ограничивает частоту заявок на один нормализованный телефон, резервирует остаток в транзакции и обрабатывает повторную отправку через уникальный идентификатор. Для высокой нагрузки/спам-атак потребуется отдельная защита от ботов.
